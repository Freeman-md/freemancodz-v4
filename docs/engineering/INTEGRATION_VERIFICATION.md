## Reusable setup and isolation

- [Disposable PostgreSQL helper](../../tests/integration/disposable-postgres.ts): `withDisposablePostgres` creates one fresh container through an explicit local Docker Unix socket, using `pgvector/pgvector:0.8.1-pg15@sha256:94aee7e88f98125114657cab98e28c5dfa8dd517a6bf83fd98b503439f1e3de6`. Provision that exact image first with `docker pull` if it is not cached; execution uses `--pull never`.
- The helper generates the password and fixture identifier in memory, publishes an ephemeral port only on `127.0.0.1`, and supplies the connection only through the child environment/callback. It validates the container label, publication and mounts. The image declares a data volume, so one fresh anonymous volume is used; host binds and pre-existing named volumes are rejected. Server identity/version are checked before creating `anon`, `authenticated` and `service_role` as NOLOGIN roles. Finalisation removes only that labelled container with its anonymous volume and verifies both are absent. Signal cleanup is scoped to that same fixture.
- [Target guards](../../tests/integration/disposable-target.ts) run before writes in all seven database suites and the two browser suites that write PostgreSQL. They reject missing/unknown fixture identity, non-loopback URLs, the normal PostgreSQL port, wrong credentials/database, extra URL options and a mismatched read-only server-identity query. A localhost-looking URL alone is insufficient. The existing optional raw-suite skips remain visible; the wrapper supplies every prerequisite and rejects zero, skipped, failed, cancelled or incomplete root TAP evidence.
- [Database runner](../../tests/integration/run-database.mjs) replays all **23 committed migrations** using the existing migration/seed helper, then executes existing integration suites serially against unique databases/visitor data. It preserves their assertions, including real SQL failures and rollback. Child output is buffered and database URLs/passwords are redacted before any log emission; raw connection errors from target validation are not exposed.
- [Browser runner](../../tests/e2e/run-workflow.mjs) keeps one app at a time in a fresh tool-owned `/tmp` directory. [Existing staging fixture](../../tests/e2e/stage-workflow-variant.mjs) copies only explicit non-secret source/config/package/Prisma/public candidates, rejects symlinks and sensitive names before reads, and links the installed dependency tree without copying it or running install hooks. Generated Prisma files and Next build outputs stay in the stage. It never invokes dotenv-based maintenance entrypoints.
- A fixture marker under `/images/__engineering_fixture.json` binds HTTP requests to the same generated fixture identity. Redirects, unknown origins and wrong markers fail before browser writes. The optional empty/services test additionally requires separate explicit fixture origins and both markers. Its dual-app journey was **not executed** here.

Available commands:

```sh
npm run test:database
npm run test:browser:workflow
npm run test:browser:workflow -- --browser-only
```

The browser command needs installed matching Playwright engines. The tested setup used `PLAYWRIGHT_MODULE=/Users/freemancodz/.npm/_npx/9833c18b2d85bc59/node_modules/playwright/index.mjs`, cached Chromium, and `WEBKIT_EXECUTABLE=/tmp/freemancodz-playwright.GAYefY/webkit-2391/pw_run.sh`. These are machine prerequisites, not portable repository dependencies; another machine must provision matching versions or set the existing executable variables. Missing prerequisites fail early with a useful diagnostic. No real provider credentials are supplied. Full invocation performs an unmodified-production-source build followed by the Meeting fixture build; `--browser-only` performs only the latter and does **not** claim production build verification.

Both builds used Next's documented `build --webpack` mode because the stage links installed dependencies outside its root. The bundled reference is `node_modules/next/dist/docs/01-app/03-api-reference/08-turbopack.md`. This verifies production-source generation/build in that supported mode; the default Turbopack build was not exercised. Installed versions: Node 22.17.0, Next 16.2.12, Prisma 7.9.1, TypeScript 6.0.3; browser driver preflight is linked in [browser prerequisites](setup/evidence/browser-preflight.md).

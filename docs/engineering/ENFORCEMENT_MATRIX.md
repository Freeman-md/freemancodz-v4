### Source scope and known limits

- Git enumerates tracked and untracked non-ignored candidates. Deleted worktree paths are removed from the scan; their baseline entries still fail stale. Existing source is not executed. Authored `.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.jsx`, `.mjs`, `.cjs` under `src` are parsed; generated code is a terminal node, not imported or inspected.
- Resolution covers the current `@/* → ./src/*` mapping, relative files/indexes, and emitted JS suffixes pointing to TS sources. Import declarations, empty imports, named/star/empty re-exports, namespace/default/inline type bindings, import-type queries and string-literal dynamic `import`/`require` are represented. The baseline matches each binding separately by rule, importer, resolved target, imported/local symbol, type/value and syntax, never by a whole directory or line number.
- Parse failures, unresolved local imports, computed `import`/`require`, import-equals declarations, package-import (`#`) and URL/absolute specifiers, unsupported CLI modes and unsupported alias configuration fail with exit **2**, not an empty passing scan. Covered policy/baseline failures exit **1**; successful non-regression exits **0**. Diagnostics name rule/path and remediation, without source snippets or environment values.
- ARC-003 covers module→app/composition, infrastructure→app/business runtime implementation and non-adapter composition consumers. ARC-002 flags parallel production roots and identifiable concrete client/repository/service imports by adapters, including established plural folders and `.repository`/`.service` suffixes. It does not infer all constructors, data access or responsibility from names. Type-only public contracts remain valid; whether they are deliberately public and injected needs review.
- ARC-006/007 reject business-module runtime infrastructure/client imports and cross-capability runtime helpers. The exact reviewed D2 Calendar/Meeting error symbols are supported only while their exporting files and runtime edges remain inert. A conservative syntax proof permits the current exported Error subclasses with bounded readonly code/outcome parameters and a safe `super` constructor; it rejects extra executable declarations, methods, calls, unbounded code types and unsafe runtime dependencies. A newly reviewed legitimate error shape requires an explicit checker/test update against D2; this recognition limit is not a new architectural prohibition or automatic approval for more exports.
- ARC-004 walks local runtime graphs from `"use client"`, including re-exports and literal dynamic imports, checking direct type-only server dependencies too. It rejects server source areas, `server-only`, Prisma, known provider SDKs and Node built-ins. External package internals, bundler transforms, conditional exports and arbitrary indirect loaders are not inspected; build/browser evidence and semantic review remain required. No dependency-cycle ban was approved or added.
- ARC-009 catches direct/bracket/computed-key `process.env`, `globalThis.process.env`, named `env` imports and default/namespace aliases of `node:process`/`process`. Whole env aliases/destructuring are findings. Only central env and the inspected target-loader forwarding shape qualify. A verified child-process import's `env: { ...process.env }` forwarding shape is not a configuration lookup; its target safety still needs review. Dotenv edges outside the infrastructure target loader are findings; the legacy entry includes the original `run` call owner/count, so a second direct loader call fails. Arbitrary alias/data-flow tricks, shadowed bindings and custom loaders are not a general taint-analysis guarantee.
- Source comment suppressions (`eslint-disable`, TypeScript ignore/expect-error/nocheck and Prettier ignore) fail STD-024: no approved exception is recorded. Only trivia gaps between AST leaf tokens are scanned: JSX/template raw text and explanatory mentions are not directives; genuine JSX-expression/template-interpolation comments remain checked. Configuration changes, suppressions in non-source documents and deliberate checker/baseline edits require independent diff review; this tool cannot protect itself from an authorised-looking edit.

### Formatter scope and secret-file safety

Before reading content, the candidate policy rejects `.env*`, secret/credential/private-key/token/cookie names, key/certificate formats, parent traversal, dependency/build/generated roots and unsupported extensions. Reads reject symlinks in the file or parent path before following them. It does not open secret examples either, and is not a secret-content scanner.

Supported formatter candidates are root-level authored Markdown/JSON/TS/JS/CSS/YAML and equivalent files under `src`, `tests`, `scripts`, `docs`, `prisma`, `.github`, plus the repository-owned architecture skill. Ordinary authored docs and all 17 source prompt snapshots are included. Imported generic skill packages, private ignored milestone state, auxiliary hidden tool/design caches, generated/build/vendor content, SQL/Prisma/TOML and non-text assets are outside this bounded formatter scope. No broad documentation exclusion or `.prettierignore` bypass is used. Prettier receives the explicit committed JSON config; no app module, environment loader, broad `format` script or formatter write runs during checking.
